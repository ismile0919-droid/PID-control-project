좋아. 그러면 이번 방학 프로젝트를 **"센서 기반 물체 추적 및 폐루프 제어 시스템"**으로 확정하고, 아예 **동아리 지원용 포트폴리오까지 염두에 둔 2학년 수준의 프로젝트**로 설계해보자.

핵심은 **기능을 많이 넣는 게 아니라, 하나의 제어 시스템을 제대로 만드는 것**이야.

---

# 1. 프로젝트 최종 형태

내가 추천하는 최종 제목은:

> **다중 거리센서 기반 이동물체 추적 및 폐루프 제어 시스템**

영어로는

> **Multi-Sensor-Based Moving Object Tracking and Closed-Loop Control System**

정도가 좋아.

최종적으로 만들 것은 이런 시스템이야.

```text
             이동하는 물체
                  ↓
        ┌─────────────────┐
        │ 거리 센서/IMU    │
        └────────┬────────┘
                 ↓
              STM32
        ┌────────┴────────┐
        │ 센서 처리       │
        │ 필터링          │
        │ 상태 추정       │
        │ PID 제어        │
        └────────┬────────┘
                 ↓
            PWM / UART
                 ↓
       ┌─────────┴─────────┐
       │                   │
    서보모터             DC 모터
   방향 추적            이동 제어
       │                   │
       └─────────┬─────────┘
                 ↓
             Raspberry Pi
                 ↓
       데이터 기록 / 시각화
```

여기서 중요한 건 **라즈베리파이가 모든 것을 제어하지 않는다는 것**이야.

---

# 2. Raspberry Pi와 MCU의 역할을 분리하자

이게 이번 프로젝트에서 상당히 중요한 학습 포인트야.

### STM32/MCU

실시간성이 필요한 것 담당:

* 센서 읽기
* ADC
* GPIO
* PWM
* 서보 제어
* 모터 제어
* 엔코더
* PID
* 인터럽트

### Raspberry Pi

상위 시스템 담당:

* Python
* 데이터 수집
* 실시간 그래프
* 로그 저장
* 파라미터 설정
* 결과 분석
* 나중에는 GUI

즉,

> **MCU = 몸의 반사신경**

> **Raspberry Pi = 두뇌/관제 컴퓨터**

라고 생각하면 돼.

이 구조는 네가 3학년 때 STM32 + Jetson + ROS2 같은 시스템을 접할 때도 상당히 도움이 될 거야.

---

# 3. 그런데 처음부터 이동로봇을 만들면 안 된다

이게 중요해.

처음부터

> 센서 + STM32 + 라즈베리파이 + DC모터 + 엔코더 + 배터리 + PID + 추적

을 한꺼번에 하려고 하면 높은 확률로 프로젝트가 꼬인다.

그래서 **계단식으로 만든다.**

---

# Phase 1 — 센서 하나 제대로 읽기

첫 번째 목표는 정말 단순하게 잡아.

### ToF/초음파 센서

예를 들어

```text
물체
 ↓
센서
 ↓
거리 = 73 cm
```

를 계속 측정한다.

그리고 Python이나 STM32에서

```text
73
72
72
71
70
...
```

처럼 데이터를 받아본다.

여기서 그냥 끝내지 말고 **센서의 오차를 직접 관찰**해.

예를 들어 물체를 고정해놓고 1000번 측정해서

* 평균
* 최대
* 최소
* 표준편차

를 구해보는 거야.

그러면 처음으로

> **"센서값은 실제값이 아니다."**

라는 아주 중요한 임베디드 개념을 경험하게 돼.

---

# Phase 2 — 필터링

센서가 이런 식으로 나온다고 해보자.

```text
100
99
101
98
135
100
99
102
```

135가 갑자기 튀었지.

이걸 그대로 제어에 넣으면 모터가 갑자기 움직일 수 있어.

그래서 간단한 필터를 적용해.

### 이동평균

예:

```text
(100 + 99 + 101 + 98 + 135) / 5
```

같은 방식.

처음에는 이동평균 정도만 해도 충분해.

그리고 나중에 여유가 있으면

* Median filter
* Exponential Moving Average
* Low-pass filter

등을 비교해봐.

이렇게 하면 단순 센서 프로젝트에서 **신호처리 프로젝트로 한 단계 올라간다.**

---

# Phase 3 — 물체의 움직임 추정

이제 단순히 거리를 측정하지 않고 **변화량을 이용한다.**

예:

```text
t = 0    100 cm
t = 0.1   98 cm
t = 0.2   96 cm
t = 0.3   93 cm
```

그러면

> 물체가 나에게 접근하고 있다.

라는 정보를 얻을 수 있지.

여기서 더 나아가면

> 물체의 상대적인 속도

까지 추정할 수 있어.

이게 바로 **센싱 → 상태 추정**의 시작이야.

---

# Phase 4 — 서보모터로 방향 추적

여기부터 프로젝트가 재미있어진다.

센서를 좌우로 움직일 수 있는 **Pan 구조**를 만든다.

```text
           물체
             ●
             ↑
             │
        ┌────┴────┐
        │  Sensor │
        └────┬────┘
             │
          Servo
             │
           Base
```

센서가 물체를 찾고 서보가 그 방향을 바라보도록 만든다.

---

# 4. 여기서 센서를 2개 사용하자

내가 처음부터 추천하는 건 **좌·우 두 개의 거리센서**야.

```text
        Left       Right
          \         /
           \       /
            \     /
             물체
```

예를 들어

```text
Left  = 70 cm
Right = 100 cm
```

라면 물체가 왼쪽에 있다는 것을 알 수 있어.

반대로

```text
Left  = 100 cm
Right = 70 cm
```

이면 오른쪽에 있는 거지.

따라서

```text
오차 = Left - Right
```

같은 값을 만들 수 있어.

그리고 목표는

> **오차 = 0**

으로 만드는 거야.

---

# 5. 여기서 폐루프 제어가 등장한다

이게 이번 프로젝트의 핵심이야.

```text
        목표 상태
           ↓
         오차 계산
           ↓
       제어 알고리즘
           ↓
         서보
           ↓
       센서 측정
           ↓
       현재 상태
           │
           └──────→ 오차 계산
```

이게 **closed-loop control**이야.

센서값을 한 번 읽고 모터를 움직이는 게 아니라,

> **움직인다 → 측정한다 → 얼마나 틀렸는지 계산한다 → 다시 움직인다**

를 계속 반복하는 거야.

---

# 6. 처음에는 P 제어부터

처음부터 PID를 구현할 필요 없어.

먼저

> **P controller**

를 구현해.

개념적으로는

**제어량 = Kp × 오차**

야.

오차가 크면 많이 움직이고,

오차가 작으면 조금 움직이는 방식이지.

예를 들어:

```text
물체가 크게 왼쪽
→ 서보 많이 왼쪽

물체가 조금 왼쪽
→ 서보 조금 왼쪽

물체가 중앙
→ 서보 정지
```

이게 제대로 작동하면 이미 **폐루프 제어 시스템**이 완성된 거야.

---

# 7. 그 다음 PID로 발전

그 다음에 PID를 붙여.

genui{"physics_motion_forces_learning_block":{"type_id":"VELOCITY_AS_SLOPE_GRAPH","locale_override":"ko-KR"}}

여기서 중요한 건 공식을 외우는 게 아니라 **각 항이 왜 필요한지 직접 관찰하는 것**이야.

### P

현재 오차에 반응.

### I

오차가 계속 누적되는 문제를 보정.

### D

오차가 변화하는 속도를 보고 과도한 움직임을 억제.

실제로

* P만 사용
* PI 사용
* PID 사용

을 각각 실험해서

**응답시간 / 오버슈트 / 진동 / 정상상태 오차**

를 비교해보면 굉장히 좋은 프로젝트가 된다.

---

# 8. 여기서 이동체를 추가한다

이제 마지막 단계야.

서보만 움직이는 시스템에서 **2륜 이동체**로 발전시키는 거야.

```text
       ┌─────────────┐
       │   Sensor    │
       └─────────────┘
          ↓       ↓
       Left       Right
       Motor      Motor
          ↓       ↓
        ○─────────○
```

물체가 왼쪽에 있으면

```text
Left motor  느리게
Right motor 빠르게
```

해서 왼쪽으로 회전.

물체가 오른쪽에 있으면 반대로.

물체가 멀면 앞으로 이동.

물체가 너무 가까워지면 정지 또는 후진.

이렇게 하면

> **물체를 따라가는 로봇**

이 된다.

---

# 9. 엔코더를 추가하면 수준이 확 올라간다

DC 모터에 엔코더가 있다면 아주 좋은 확장 기능이야.

예를 들어 목표 속도:

```text
100 RPM
```

인데 실제 측정값이

```text
83 RPM
```

이라면 PWM을 더 올리는 식으로 제어할 수 있어.

즉,

```text
목표 RPM
   ↓
오차
   ↓
PID
   ↓
PWM
   ↓
모터
   ↓
Encoder
   ↓
실제 RPM
   └──────→ 피드백
```

이건 정말 전형적인 **임베디드 제어 시스템**이야.

---

# 10. Raspberry Pi는 여기서 빛난다

라즈베리파이에서는 Python으로 실시간 데이터를 받아서 그래프를 그려.

예를 들어:

```text
시간 ───────────────→

목표 거리
──────────────

실제 거리
╲___╱╲____╱╲____

오차
```

그리고 CSV로 저장해.

```text
time,distance,error,pwm
0.00,100,20,45
0.01,98,18,41
0.02,95,15,35
...
```

이 데이터를 가지고 나중에

* PID gain에 따른 응답 차이
* 센서 필터에 따른 노이즈 차이
* 추적 정확도
* 응답 시간

등을 분석할 수 있어.

이렇게 해야 **"로봇이 움직였다"에서 끝나지 않고 실험 결과가 있는 프로젝트**가 돼.

---

# 11. 최종적으로 평가 지표를 만들자

이 부분을 꼭 넣었으면 좋겠어.

예를 들어:

### 추적 오차

목표 각도와 실제 각도의 차이.

### 거리 오차

목표 거리와 실제 거리의 차이.

### Settling time

목표 상태에 도달해서 안정되는 데 걸리는 시간.

### Overshoot

목표를 지나쳐서 반대 방향으로 다시 돌아오는 정도.

### 센서 노이즈

필터 적용 전후의 표준편차.

이런 데이터를 보여주면 동아리 면접에서

> "제가 PID를 구현했습니다."

보다

> "P 제어에서는 평균 오차가 이 정도였고, PID를 적용하면서 settling time과 overshoot가 이렇게 변했습니다."

라고 이야기할 수 있어.

**이 차이가 굉장히 커.**

---

# 12. 프로젝트 난이도는 이렇게 단계적으로 올리자

| 단계 | 내용           | 목표        |
| -- | ------------ | --------- |
| ①  | 센서 측정        | 거리값 취득    |
| ②  | 필터           | 노이즈 제거    |
| ③  | 움직임 추정       | 거리 변화 분석  |
| ④  | 서보           | 물체 방향 추적  |
| ⑤  | P 제어         | 폐루프 제어    |
| ⑥  | PID          | 제어 성능 개선  |
| ⑦  | DC 모터        | 이동체 구현    |
| ⑧  | 엔코더          | 속도 피드백    |
| ⑨  | IMU          | 자세 정보     |
| ⑩  | Raspberry Pi | 데이터 로깅/분석 |
| ⑪  | 센서 융합        | 최종 도전     |

**①~⑥만 해도 성공적인 프로젝트**로 인정할 수 있어.

⑦~⑩까지 가면 상당히 좋은 2학년 개인 프로젝트가 되고,

⑪까지 제대로 하면 상당히 욕심낸 프로젝트가 돼.

# 13. 이번 방학에는 욕심을 어디까지 내야 하나?

네 상황에서는 **⑩까지를 1차 목표**로 잡는 걸 추천해.

즉 최종 목표는:

> **"거리 센서로 이동 물체의 위치를 측정하고, 필터링된 센서 데이터를 이용하여 상태를 추정한 뒤, PID 제어를 통해 서보 및 이동체를 자동 제어하고, Raspberry Pi에서 전체 데이터를 실시간으로 기록·분석하는 시스템."**

여기에 **IMU/센서 융합/Kalman filter는 도전 과제**로 남겨.

## 최종적인 프로젝트 구조

```text
                [Moving Target]
                       ↓
             ┌─────────────────┐
             │ Distance Sensors │
             └────────┬────────┘
                      ↓
                    STM32
                      ↓
              Signal Filtering
                      ↓
                State Estimation
                      ↓
                 Error 계산
                      ↓
                 PID Control
                      ↓
               PWM / Motor
                      ↓
              Target Tracking
                      │
                      └───────┐
                              ↓
                       Raspberry Pi
                              ↓
                    Python Data Logger
                              ↓
                    Graph / Analysis
                              ↓
                         GitHub
```

이게 이번 방학의 **메인 프로젝트**가 되는 거야.

그리고 나는 여기서 **"Raspberry Pi를 샀으니 Raspberry Pi를 최대한 많이 써야 한다"는 생각은 버리는 걸 추천해.** 이번 프로젝트에서 라즈베리파이의 가장 좋은 역할은 **실시간 제어를 억지로 담당하는 게 아니라, MCU와 상위 컴퓨터 사이를 연결하고 데이터를 분석하는 것**이야.

이렇게 만들면 3학년 때 동아리에 들어가서 **STM32 + ROS2 + IMU + 모터 + 센서융합** 같은 프로젝트로 넘어갈 때도 상당히 자연스럽게 이어질 거야.
